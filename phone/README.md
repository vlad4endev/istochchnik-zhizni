# Моя церковь — телефон

Отдельное приложение на Flutter для Android и iOS. Оно ходит в тот же API, что и сайт (`https://app.church-tambov.ru` по умолчанию).

## Запуск

```bash
cd phone
flutter pub get
flutter run
```

Адрес сервера можно сменить в «Ещё → Настройки». Для эмулятора Android локальный API обычно `http://10.0.2.2:40978`.

`flutter run -d chrome` открывает ту же вёрстку в браузере. Браузер блокирует запросы на другой домен, поэтому вход с продакшен-сервера проверяйте на телефоне или эмуляторе.

## Сборка для проверки на телефоне

Два файла в [`releases/`](releases/), выбирайте по телефону:

- [`moya-cerkov-arm64.apk`](releases/moya-cerkov-arm64.apk) (≈45 МБ) — почти все телефоны последних лет. Пробуйте сначала его.
- [`moya-cerkov-armv7.apk`](releases/moya-cerkov-armv7.apk) (≈37 МБ) — старые 32-битные телефоны.

Нужен Android 7.0 или новее (на более старых система пишет «пакет не обрабатывается»; Flutter ниже 7.0 не поддерживает). Скачайте файл на телефон и откройте. Система попросит разрешить установку из этого источника.

На рабочем столе приложение называется «Моя церковь», пакет `com.istochnikzhizni.molitva.preview`. Оно стоит рядом с уже установленным церковным приложением и не заменяет его. Вход — тот же телефон и пароль, сервер `https://app.church-tambov.ru`.

**Подпись.** Все тестовые сборки подписаны одним общим тестовым ключом `android/app/shared-test.keystore` (публичный отладочный ключ, пароль `android`; в магазин не годится). Раньше ключ создавался заново в каждой среде сборки, и телефон не ставил новую сборку поверх старой. Если у вас стоит *старая* тестовая сборка, подписанная другим ключом, и новая не ставится («приложение не установлено», «не удалось обработать пакет», «конфликтует с существующим») — один раз удалите старую «Моя церковь» (тестовую, пакет `.preview`) и поставьте новую. Дальше обновления будут ставиться поверх.

**Если файл «не обрабатывается» («пакет не обрабатывается», «проблема при синтаксическом анализе пакета»).** Три причины: (1) файл повредился при пересылке (мессенджер, облако) — сверьте размер файла в байтах с указанным при отправке или скачайте заново прямо из репозитория; (2) телефон старше Android 7.0; (3) файл не от того процессора — тогда система пишет «не установлено», попробуйте второй файл. Файл должен называться `.apk` (не `.apk.1`, не `.zip`).

Пересобрать тестовые APK (номер сборки `+N` в `pubspec.yaml` каждый раз увеличивайте; код версии телефона = N + 4000 для armv7 и N + 5000 для arm64, и он должен быть больше прежних, иначе обновление не встанет поверх):

```bash
cd phone
PREVIEW_BUILD=1 flutter build apk --release --split-per-abi --target-platform android-arm,android-arm64
cp build/app/outputs/flutter-apk/app-arm64-v8a-release.apk releases/moya-cerkov-arm64.apk
cp build/app/outputs/flutter-apk/app-armeabi-v7a-release.apk releases/moya-cerkov-armv7.apk
apksigner verify --print-certs releases/moya-cerkov-arm64.apk   # подпись ae03a819…
```

Без `PREVIEW_BUILD=1` получится обычная сборка с пакетом `com.istochnikzhizni.molitva` и тем же названием «Моя церковь». Сборку для iPhone эта машина не делает: для неё нужен Mac.

## Дизайн

Вёрстка повторяет макет «Моя церковь» (экраны в `mobile/*.dc.html`): винная шапка с мягкими пятнами света, кремовый лист со скруглением 30, тёмная нижняя панель с янтарной вкладкой. Шрифты — Onest и Playfair Display Italic (Google Fonts, лицензия SIL OFL 1.1), лежат в `assets/fonts`.

Всё общее собрано в `lib/ui/kit/`:

- `tokens.dart` — цвета, отступы, радиусы, типографика, светлая и тёмная палитры листа (`context.palette`) и пастельные тона плиток (`Tone`);
- `scaffold.dart` — каркас экрана `ChurchPage`, кнопки шапки и тёмный экран `DarkPage`;
- `components.dart` — карточки, строки списков, плитки разделов, кнопки, сегменты, чипы, поля, аватары, бейджи;
- `bottom_nav.dart` — нижняя панель вкладок.

Новый экран начинайте с `ChurchPage`, а цвета берите из `context.palette` — тогда он сразу работает в светлой и тёмной теме.

## Что уже есть

- **«Ещё»:** карточка профиля сверху, поиск по разделам, разделы по группам («Служение и музыка», «Слово», «Жизнь церкви»). Администратору — блок «Для администраторов»: крупная кнопка «Админка на сайте» (`/admin` в браузере), «Заявки» со счётчиком ожидающих и быстрые ссылки в вкладки веб-админки (пользователи, разделы приложения, права ролей, уведомления, Telegram, группы и каналы, журнал, диагностика — `/admin?tab=…`).
- **«Мой профиль»:** шапка с фото (нажмите, чтобы сменить), «О себе» (имя, фамилия, почта, день рождения), молитвенная нужда, роли и направления служения (только чтение — назначает администратор), уведомления, ссылка на страницу на сайте, смена пароля по нажатию. «Сохранить» появляется внизу только при изменениях, уходит только изменённое; при выходе с несохранённым — вопрос.

- **Нижнее меню** — полупрозрачная панель на всю ширину, как в iOS: размытый фон, тонкая линия сверху, контент прокручивается под ней; активная вкладка на тонированной плашке, бейдж непрочитанных у «Чатов». Подписи не растут больше 125% системного шрифта.

Вход и заявка, профиль с фото и нуждой, лента с публикацией и комментариями, сторис с видео, молитва, чаты с фото, файлами, голосом, опросами и новым диалогом, звонок, Библия, песенник с аккордами, проповеди с плеером и конспектами, мероприятия, служение, расписание, студия, трансляция и заявки администратора. Уже открытые разделы остаются на телефоне, если сеть пропала.

Разделы скрываются по тем же правилам ролей, что и на сайте (`/api/settings/sections`).

## Песенник

- Список по алфавиту (или по номеру) с закреплёнными буквами и указателем справа; список хранится в файле на телефоне, поэтому открывается и ищется без сети.
- Поиск мгновенный и работает офлайн: по названию, номеру, тональности, тегам и тексту (находит строку и подсвечивает слова). Фильтры: избранное, теги, тональность, темп.
- Читалка: аккорды над слогами, транспонирование и каподастр (запоминаются для каждой песни, есть «Сбросить»), «концертные аккорды», размер шрифта, темы (чёрная/тёмная/светлая), автопрокрутка (касание останавливает), экран не гаснет.
- Нотация: в песне без `H` натуральная си — `B`; в песне с `H` одиночный `B` — си-бемоль.

## Библия

- Главная: одно поле поиска понимает и ссылку («Ин 3:16», «1 Кор 13», «Пс 22» — работает без сети), и название книги по началу («иоан»), и слова из текста (с подсветкой; нужен интернет). Карточка «Продолжить чтение» ведёт на место, где остановились (запоминается на телефоне и на сервере, с других устройств подхватывается более новое), недавние главы — чипами, книги — плитками по заветам.
- Читалка: главы листаются свайпом сквозь границы книг (из Бытия 50 в Исход 1) и кнопками внизу; выбор книги и главы — по заголовку. Нажатие на стих выделяет его: копировать с ссылкой, подсветить, оставить заметку (заметки общие с веб-версией и видны в конце главы). Настройки: размер шрифта, тема (как в приложении, светлая, тёмная, чёрная), номера стихов, каждый стих с новой строки. Прочитанные главы лежат в файлах на телефоне и открываются без сети.
- Переводы берутся с сервера (в читалке — чип с названием перевода); если в переводе нет книги (например, Ветхого Завета), читалка начнёт с первой доступной.
- **Стих дня** на главной (`widgets/verse_of_day_card.dart`): тот же список из 75 стихов и та же формула по дате, что на сайте, — у всех в один день один стих. Нажатие открывает стих в главе, кнопка отправляет. Если текста нет (нет сети, в переводе нет книги), карточки нет.
- **Закладки** (общие с сайтом, `/api/bible/bookmarks`): в панели над выбранными стихами «Закладка» / «Убрать». Подряд идущие стихи — одна закладка-диапазон, несвязные — по одной на группу. В тексте у стиха значок. Список — «Закладки» на главной Библии: вкладки «Заметки · N» и «Закладки · N», нажатие открывает место, удаление с понятным сообщением при сбое.
- **Панель действий над стихами**: Закладка, Заметка, Слушать с этого стиха (если у главы есть озвучка), Копия, Цвет (подсветка), Отправить. «Отправить» открывает системное окно «Поделиться» (`core/share_text.dart` → канал `church/system`); если окна нет — копирует в буфер.
- **Озвучка** (`audio/`, `widgets/audio_widgets.dart`): в начале главы «Слушать главу»; читаемый стих подсвечивается, текст прокручивается за ним; плеер — перемотка, ±15 с, скорость 0,75–2× (по кругу), «Включать следующую главу», таймер сна (5/10/15/30 мин и «до конца главы»). Плеер один на всё приложение (`BiblePlayer.instance`): звук не обрывается при переходе между экранами, а мини-плеер виден и в читалке, и на главной Библии, и над нижним меню приложения. В конце главы читалка сама листает дальше; если читалка закрыта — плеер подгружает следующую главу сам. Скорость и автопереход запоминаются. **Ограничение:** фонового режима с уведомлением-плеером нет (`just_audio_background` допускает только один плеер, а в приложении ещё голосовые и проповеди), при выключенном экране Android может остановить звук.
- **Планы чтения** (`plans_page.dart`): список с прогрессом, создание («Евангелия за 30 дней», срок 7–90 дней — план раскладывает сервер), на странице плана «Читать сейчас», отметки дней (сразу видны, при сбое откатываются), ссылки открывают чтение, удаление с подтверждением.
- **Комментарии к главе** (Лопухин и церковные) показаны под текстом. Писать церковные комментарии можно только на сайте.
- **Сервер:** личные действия в Библии (место чтения, заметки, закладки, планы) раньше отвечали 403 для ролей «Пользователь» и «Прихожанин» — их не было в белом списке `roleAccess.ts`; теперь разрешены (нужен передеплой сервера, иначе заметки и закладки у этих ролей не сохранятся — и в приложении, и на сайте).

## Расписание и служение

- **Расписание → «Мои».** Одна лента назначений из медиа, музыки и воскресного служения: сверху ближайшее («Завтра», «В воскресенье, 22 ноября») с кнопками «Подтвердить» и «Не смогу», ниже по неделям. «Подтвердить все» отвечает на всё сразу; отказ просит подтверждения, ответ можно изменить. Лента хранится на телефоне и открывается без сети.
- **Расписание → «Команда».** Кто в какой роли служит на выбранной неделе (стрелки ‹ ›, «К этой неделе»). Видно только те служения, к которым есть доступ (правила как на сайте: направление служения, служебная роль, роль в приложении). Координаторы (админ, медиа-менеджер, музыкальный лидер) назначают и снимают людей с ролей; пастор и админ меняют ведущего и проповедника воскресного собрания.
- **Служение.** Программы по вкладкам «Предстоящие» и «Прошедшие». В программе: время начала каждого блока и конец служения (считается по длительностям), мои блоки отмечены, песня открывает песенник с аккордами, место Писания проповеди — читалку Библии, дни рождения и расписание недели, команда трансляции, кнопка «Скопировать программу» для отправки в чат. Программа загружается по публичной ссылке плана (в ней есть названия песен и имена); если ссылка устарела, берутся данные плана и справочники. Открытые программы сохраняются на телефоне.
- **Редактор программы (админ и служитель, как на сайте).** Кнопка «+» в «Служении» — новая программа по шаблону на выбранную дату. Нажатие на программу открывает редактор: настройки (дата, начало, ведущий, проповедник, ответственные за музыку и стихи — выбор из подходящих людей, «показать всех»), блоки со временем начала, перетаскивание за ручку, добавление блока и разделителя, правка блока (название, тип, длительность, ответственный, песня из каталога, тема и стихи проповеди, стих, заметки, метка и значок, «сцена перед блоком», скрытие в публикации), удаление с «Отменить». Проповедь всегда за проповедником, песни — за ответственным за музыку (как на сайте). Автосохранение через 0,8 с (только изменённые блоки), при ошибке — «Повторить». «Опубликовать»/«Вернуть в черновик» (при повторной публикации спрашивает про рассылку; сервер обновляет сетлист в Студии), «В архив», «Удалить», «Скопировать ссылку/программу», «Посмотреть как участник». Вкладка «Архив».
- **Шаблоны программ** (админ, служитель и «Ведущий»): кнопка «Шаблоны» в шапке «Служения» → список (выключенные с пометкой) → «+» новый шаблон. Редактор: название, описание, время начала, повтор (каждую неделю в выбранный день; «своё правило» с сайта сохраняется, пока вы его не замените), «Шаблон включён», блоки с перетаскиванием, добавлением, разделителем, удалением с «Отменить»; в блоке — тип, длительность, песня и ответственный по умолчанию, заметки. «Подтянуть из другого шаблона» заменяет блоки, время и повтор (у нового шаблона имя становится «… (копия)»). Сохранение кнопкой, при выходе с несохранёнными правками — вопрос. «Сохранить как шаблон» в меню программы (только админ) открывает редактор с блоками программы и ответственными по умолчанию.
- Не сделано в приложении: файлы к проповеди, PDF программы, «Сейчас открыто у других участников», ручной выбор «текущего блока».

## Студия

- **Сетлисты.** Ближайшие, без даты и прошедшие; новый сетлист создаётся с названием и датой. Внутри: порядок песен перетаскиванием, добавление из песенника (если есть своя версия песни, приложение спрашивает, какую взять), удаление с подтверждением, переименование, дата, удаление сетлиста и ссылка для команды (включение доступа и копирование). Менять можно только свои сетлисты; сетлисты из программы служения команда видит и играет, но не правит.
- **Играть сетлист.** Режим выступления: песни листаются свайпом или кнопками, внизу «Песня 3 из 8» и название следующей, экран не гаснет. В каждой песне работают транспонирование, каподастр, размер шрифта и автопрокрутка, как в песеннике; заметки музыканта к строкам и участкам текста показываются под песней.
- **Мои песни.** Свои версии песен (свой текст и тональность) открываются с аккордами.
- Сетлисты и сыгранные песни сохраняются на телефоне: на репетиции и на сцене работают без сети (менять без сети нельзя).
- Не сделано: редактирование текста и аккордов, черновики, заметки музыканта (только просмотр), отчёт об использовании песен — остаются на сайте.

## Молитва и главная для координаторов

Как в PWA. Что видит каждый — решает роль: приложение прячет лишнее, а настоящую проверку делает сервер.

- **«Молитва» (все).** Плашка с датой раскрывает календарь: неделя со стрелками или «Весь месяц». Ниже карточки дня: член церкви, тема со стихом, служения и «Молимся за отпавшего». Срочной нужды и объявления здесь нет — они на главной.
- **«Молитва» (координатор, пастор, админ).** Кнопка «Сбор нужд · очередь недели»: эта и следующая неделя, прогресс, поиск и фильтры; по тапу на день — лист с нуждой (можно «Улучшить с ИИ»), кураторами и справкой о прошлых нуждах. Автораспределение — кнопка в шапке, с подтверждением. У админа рядом значок «Рассылка в Telegram» (превью, подтверждение, отправка). Пастор и админ видят «Сегодня раздел открыли N человек».
- **Главная (все)** — по образцу мобильной версии сайта, сверху вниз: три кнопки («Мероприятия», «Отправить нужду», «Проповеди»); дни рождения недели; карточка «Богослужение» (проповедник и ведущий с фото или инициалами, кнопка «написать», тема, стих, «Оценить» после служения); «Твоё служение на этой неделе» (подтвердить или отказать); срочная нужда и объявление; «Молимся сегодня»; трансляция (в эфире или за два часа до начала); «Медиа»; «Мероприятия» (по тапу — описание и афиша). Прихожанин не видит «Отправить нужду», объявление и «Молимся сегодня».
- **Главная (координатор сбора и админ).** Круглая кнопка «+»: срочная нужда или объявление — создать, изменить, удалить, выбрать срок («сегодня», «до конца недели», «до конца месяца»). Блок «Координаторам сбора».

Не перенесено: правка и удаление «прошлых нужд» (в приложении они только читаются и подставляются в текст), расписание автоматической Telegram-рассылки.

## Вход и срок сессии

- Токен доступа на сервере живёт 60 минут (`AUTH_ACCESS_TOKEN_TTL_MINUTES`), а cookie обновления — 90 дней (`AUTH_REFRESH_TOKEN_TTL_DAYS`). Раньше приложение cookie не хранило и при первом 401 выкидывало на вход, то есть примерно раз в час.
- Теперь `SessionController` запоминает cookie обновления из `Set-Cookie` при входе и регистрации (в защищённом хранилище, ключ `auth_refresh`) и продлевает сессию само: заранее (за 2 минуты до конца токена, срок читается из JWT) и после ответа 401 (запрос повторяется с новым токеном). Одновременные запросы ждут одно продление; сервер меняет cookie при каждом продлении, новое запоминается — так сессия «скользящая» и живёт до 90 дней без входа.
- На вход выводит только отказ сервера в продлении (токен отозван или истёк). Нет связи или сбой сервера — человек остаётся в аккаунте.
- Кто вошёл в старой версии, один раз войдёт заново: у него cookie обновления ещё не сохранён. Сервер менять не нужно.

## Чаты

Как в Telegram и на сайте.

- **Группы и каналы.** Над первым сообщением пачки — имя автора своим цветом, рядом с последним — аватар (или инициалы). Тап по имени или аватару открывает личный чат с человеком. В личных чатах авторов не пишем. Разделители дат «Сегодня», «Вчера», «13 апреля 2025».
- **Профиль.** Тап по шапке чата. Личный: аватар, «в сети» или «был(а) …», быстрые действия (чат, звонок, звук), телефон (тап — позвонить, кнопка — скопировать), день рождения со значком «через N дней», служение, направление, роль, общие фото, файлы и ссылки. Группа: описание, «N участников, M в сети», список (владелец, админы, затем «в сети») с метками ролей; тап по участнику — «Написать».
- **Ссылки.** Адреса в сообщениях кликабельны и открываются в браузере; под сообщением карточка с картинкой, сайтом, заголовком и описанием (не больше двух; для адресов самого приложения карточки нет).
- **Меню сообщения.** Тап или долгое нажатие: сверху быстрые реакции (❤️ 👍 😂 😮 😢 🙏 🔥) и «+» с полным каталогом эмодзи; ниже — ответить, копировать, переслать, редактировать, закрепить, «кто прочитал», удалить (только то, что разрешено правилами чата). Реакции — значками под сообщением, тап по значку ставит или снимает свою. Свайп сообщения к центру — «ответить».
- **Поле ввода.** Скрепка слева от поля, смайлик внутри строки справа; он открывает каталог эмодзи под полем (поиск, «недавние», оттенки кожи); баннер «Ответ» и «Редактирование»; скрепка и голосовое — только если у вас есть право на медиа; в меню вложений: фото из галереи (несколько сразу), видео, «Снять фото», файл, опрос — над полем идёт полоса прогресса «Отправка 2 из 3 · название · 45%», а сбой одного файла не мешает остальным и объясняется по имени файла (видео уходит как «image», как на сайте, и показывается плиткой с кнопкой воспроизведения); в каналах, где писать нельзя, вместо поля пояснение.
- Новые сообщения, реакции и правки приходят сами (сокет), а история подгружается при прокрутке вверх.

Не сделано: закреплённые сообщения вверху чата, поиск по чату, создание группы, управление участниками и правами, видеозвонки из профиля.

## Видео- и аудиоконференции

Как в веб-версии: конференция по ссылке без звонка конкретному человеку.

- **Из списка чатов:** в шапке раздела «Чаты» одна кнопка «Конференция» (рядом с «Новым сообщением») — выбор «Видеоконференция», «Аудиоконференция» или «Войти по ссылке». Создаётся отдельная встреча без чата (как Телемост). В самих чатах (личных и группах) конференций нет.
- Название до 80 символов; пустое — сервер подставит «Видеовстреча»/«Аудиовстреча».
- Шаблоны «Утренняя/Вечерняя молитвенная стража» видны пастору, администратору и координатору сбора молитвенных нужд.
- После создания «название + ссылка» копируются в буфер; в окне встречи плашка со ссылкой копирует её повторно. Участники заходят по ссылке из веба (`/call/join/…`).
- **Вход по ссылке в приложении:** кнопка «Войти по ссылке» в шапке «Чаты» и «Звонки» (ссылку или «название + ссылку» можно вставить; если она в буфере — подставится сама), либо нажатие на ссылку-приглашение в сообщении чата. Откроется экран встречи: название, участники, микрофон/камера → «Войти во встречу». Причины отказа показываются по-русски (истекло, отозвано, завершена, лимит исчерпан). Выход приглашённого не завершает встречу для остальных.
- Открытие ссылки из браузера/мессенджера сразу в приложении (Android App Links) пока не сделано.
- **Окно встречи (как в вебе):** тёмный фон, сверху название, качество связи, число участников и переключатель «Сетка / Говорящий крупно»; плитки участников со скруглением, видео или портрет с инициалами, плашка «микрофон + имя», синее кольцо у говорящего, «+N» при переполнении; ссылка-приглашение сворачивается, когда кто-то подключился; внизу размытая панель: микрофон, камера, участники, ссылка, красная «Выйти» (у организатора меню «Выйти из встречи» / «Завершить для всех»). Разговор один на один: видео собеседника на весь экран, своя камера в углу, таймер.
- **Звонки из личного чата:** в шапке «Позвонить» и «Видеозвонок».

Не проверено на устройстве: доступ к камере/микрофону и сама видеосвязь (LiveKit) — нужен реальный телефон и включённые на сервере звонки.

## Уведомления и звонки (Android)

**Исходящий звонок.** Пока собеседник не ответил, на экране «Вызываем…»; время разговора идёт с его ответа. Если он отклонил, не ответил или отменил, экран закрывается с сообщением тремя независимыми путями: событие сокета (`call:rejected`…), закрытие комнаты LiveKit сервером и опрос `GET /api/calls/:id` каждые 3 секунды (на случай потерянного события). Подключение ускорено: аудиосессия настраивается параллельно с запросом к серверу, микрофон и камера включаются при входе в комнату (`fastConnectOptions`), а долгое подключение не висит бесконечно — через 30 секунд «Повторить»; во время подключения на экране виден текущий шаг («Принимаем звонок…», «Подключаемся к серверу звонков…»).

**Экран входящего звонка.** Системный экран (когда звонок пришёл при свёрнутом приложении или на заблокированном экране) оформлен под приложение: макет `android/app/src/main/res/layout/activity_callkit_incoming.xml` заменяет макет библиотеки `flutter_callkit_incoming` (те же идентификаторы представлений), фон — `assets/call/call_background.png`, сверху логотип и «МОЯ ЦЕРКОВЬ», крупный аватар (без фото — логотип церкви), имя и тип звонка, две одинаковые кнопки «Отклонить» / «Ответить». Цвета кнопок — `res/values/call_colors.xml`. При обновлении библиотеки сверьте идентификаторы в её `activity_callkit_incoming.xml`.

**Непрочитанные.** Открытый чат отмечается прочитанным на сервере (`POST /api/messenger/conversations/:id/read`) до последнего полученного сообщения: счётчик в списке и значок на вкладке «Чаты» сбрасываются, собеседник видит «прочитано». Свёрнутое приложение сообщения не читает — отметка ставится при возврате. Значок на вкладке обновляется по событиям чата и при возврате в приложение.

**Проверка уведомлений.** «Ещё → Мой профиль → Уведомления и звонки → Проверить уведомления» проходит всю цепочку и показывает, на каком шаге сбой: разрешение → запуск Firebase → токен устройства → сервер принял токен → сервер подключён к Firebase и видит устройство → тестовый пуш (`POST /api/notifications/test`, коды ошибок FCM расшифрованы по-русски). Если сервер отправил, а пуша нет — дело в телефоне (разрешение, экономия батареи).

**Звук, значок и экран блокировки.** Каналы уведомлений создаёт нативный код (`NotificationChannels.kt`, класс `ChurchApplication`) при каждом старте процесса, в том числе когда пуш разбудил закрытое приложение: громкий звук, высокая важность, показ текста на экране блокировки. Свойства канала система запоминает при первом создании, поэтому добавлены новые каналы `messages_v2` и `general_v2`; сервер шлёт в них устройствам приложения (`device_id` с префиксом `flutter-`, `src/lib/fcmChannels.ts`), остальным — в прежние каналы. Для этого нужно обновить сервер. Значок в строке состояния — белый крест (`drawable-*/ic_stat_notify.png`), цвет — винный. В «Проверить уведомления» есть шаг «Каналы уведомлений»: он показывает, не оказался ли канал беззвучным, и открывает системные настройки канала.

**Если «Токен устройства» красный («FCM Registration failed»).** Экран проверки теперь сначала проверяет связь с Google (`firebaseinstallations.googleapis.com` по HTTPS и `mtalk.google.com:5228` по TCP): если красный шаг «Связь с Google» — блокирует сеть (смените Wi‑Fi на мобильную, выключите VPN). Если связь есть, а токена нет — ключ Firebase не принимает пакет `.preview`. Тогда администратору в Firebase-консоли проекта `mychurch-29bce`: добавить Android-приложение `com.istochnikzhizni.molitva.preview` с SHA-1 тестового ключа `93:39:19:12:CD:00:3A:BF:A0:96:CE:99:10:C8:A9:47:C7:E0:28:2A`, и в Google Cloud → «Учётные данные» проверить ограничения ключа `AIzaSyBBRmpz…` (разрешить этот пакет и SHA-1 или снять ограничение по приложению). Получение токена приложение повторяет само (через 20 с, 2 и 10 минут и при возврате в приложение).

**Firebase в нативном слое.** `android/app/src/main/res/values/firebase_config.xml` содержит идентификаторы проекта церкви (то, что обычно генерирует `google-services.json`). Без него Firebase стартует только после Flutter, и пуши при закрытом приложении не доходят. Значения должны совпадать с `lib/core/firebase_config.dart`.


- Пуши идут через тот же проект Firebase, что у текущего Android-приложения церкви (`lib/core/firebase_config.dart`). После входа устройство регистрируется на сервере (`/api/notifications/save-token`), перед выходом отвязывается (`remove-token`).
- Сообщения и уведомления церкви, когда приложение свёрнуто или закрыто, Android показывает сам: каналы «Сообщения» и «Уведомления церкви», монохромная иконка. Пока приложение открыто, уведомление показывает само приложение, кроме сообщений из чата, который сейчас на экране. Нажатие открывает нужный чат.
- Входящий звонок приходит тихим приоритетным пушем `incoming_call`. Приложение показывает системную звонилку на весь экран поверх блокировки, с рингтоном и кнопками «Ответить» / «Отклонить» (пакет `flutter_callkit_incoming`). «Ответить» сразу соединяет, «Отклонить» сообщает серверу, даже если приложение было закрыто. Если звонящий отменил вызов, звонилка снимается (`call_ended` / `call_cancelled`), а неотвеченный вызов остаётся пропущенным в шторке.
- Пока приложение открыто, звонок приходит по сокету и показывается экраном приложения. Повторный пуш о том же звонке второй экран не открывает.
- На Android 14+ после первого входа приложение один раз попросит разрешить звонки на весь экран. Без этого разрешения звонок придёт обычным уведомлением.

Как проверить на телефоне:

1. Поставить APK, войти, разрешить уведомления и звонки на весь экран.
2. Свернуть приложение, написать этому человеку с сайта: должно прийти уведомление, нажатие открывает чат.
3. Заблокировать телефон, позвонить с сайта: звонилка на весь экран с рингтоном. «Ответить» соединяет.
4. Позвонить и сбросить вызов на сайте до ответа: звонилка пропадает, в шторке остаётся пропущенный.
5. Смахнуть приложение из недавних и повторить пункт 3.

В профиле есть блок «Уведомления и звонки»: видно, включены ли уведомления, разрешён ли звонок на весь экран и зарегистрировано ли устройство на сервере (или почему нет), с кнопками перехода в системные настройки. Токен устройства отправляется с повторами (15 с, 1 мин, 5 мин и при возврате в приложение). Разрешение на звонок поверх блокировки и выключенные уведомления напоминаются не чаще раза в неделю.

## Меню чата по долгому нажатию

В списке «Чаты» долгое нажатие открывает меню, как на сайте: закрепить/открепить, убрать/включить звук, очистить переписку (у всех участников, с подтверждением), удалить чат. Создатель группы или канала видит «Удалить группу/канал» — они удаляются у всех; остальные просто выходят из беседы. Закреплённые чаты сервер ставит наверх списка, у закреплённого и «без звука» чата в строке есть значок. Папки «Личное/Служение» из веб-версии в приложении не нужны: там нет вкладок по папкам.

## Быстрое открытие разделов (кеш ответов)

Разделы не грузятся заново при каждом открытии: `lib/core/http_cache.dart` — перехватчик HTTP-клиента, который показывает то, что уже видели, а свежее подтягивает фоном.

- **Открытие.** Если по адресу есть сохранённый ответ, экран получает его сразу, а приложение параллельно спрашивает сервер (не чаще раза в 3 с на адрес). Если ответ другой — сохраняется новый и `session.cache.changes` сообщает экранам, они перечитываются сами (`CacheWatcher`, `lib/core/cache_watch.dart`). Первая загрузка без сохранённого — как раньше.
- **Что кешируется.** Только список разрешённых адресов (`_cacheablePaths`): календарь, лента, проповеди, трансляции, звонки (история), список чатов, программы, шаблоны, расписания, студия, профили. Звонки (`/api/calls/<id>`), токены, счётчики, сообщения чата, песни и Библия идут напрямую (у песенника и Библии своё хранилище).
- **Как новое попадает сразу.** (1) потянули вниз — `HttpCache.fresh` берёт только с сервера; (2) своё изменение стирает сохранённое по разделу («семья»: служение/программы/расписания/студия, календарь, лента и т. д.), чтобы старое не мелькнуло; (3) пришёл пуш — связанные разделы перепроверяются (`cachePrefixesFor`); (4) событие чата из сокета обновляет список чатов; (5) возврат в приложение и раз в минуту, пока оно открыто, перепроверяется то, чем недавно пользовались.
- **Личное.** Папка `http_cache/<id участника>` в каталоге приложения; при выходе из аккаунта стирается всё. При запуске сохранённое читается в память до первого экрана (`warm`), запросы диск не ждут.
- **Загрузка.** Спиннер появляется только если ждать дольше ~0,2 с — быстрые открытия не мигают.
- **Офлайн.** Без сети показывается сохранённое; отдельной плашки «нет связи» у разделов с кешем теперь нет (она осталась только там, где данных в кеше нет).

## Статус «в сети»

`lib/core/presence.dart` повторяет логику веб-версии: сокет при подключении присылает список тех, кто в сети (`ready.onlineMembers`), дальше события `presence:online` / `presence:offline` (с временем визита). В списке чатов у личных чатов собеседник в сети — зелёная точка на аватаре; в шапке чата и в профиле — «в сети» или «был(а) …», обновляется сразу. При обрыве сокета статусы сбрасываются (лучше ничего не показать, чем показать неправду).

## Чаты «как в Telegram»

Что уже есть и откуда берётся:

- **«печатает…»** — `lib/core/typing.dart` + события сокета `typing:start/stop`; в шапке чата (акцентным цветом), в списке вместо последнего сообщения. Свой набор текста уходит на сервер не чаще раза в 3 с.
- **Черновики** — `lib/core/drafts.dart`: недописанное сохраняется на телефоне по чатам, возвращается при открытии, в списке «Черновик: …»; стираются при выходе из аккаунта.
- **Закреплённое** — панель под шапкой (`PinnedBar`): тап ведёт к сообщению, если закреплённых несколько — по кругу («2 из 3»); крестик открепляет (при наличии права).
- **Переход к сообщению** — цитата «в ответ на…», закреплённое и результат поиска прокручивают чат к нужному сообщению и подсвечивают его; старые сообщения догружаются сами (`ThreadController.ensureLoaded`).
- **Поиск** — кнопка «лупа» в чате (по этому чату) и поле поиска в списке (по названиям и по тексту сообщений во всех чатах).
- **Список чатов** — «Вы:» в группах, галочки «отправлено/прочитано» у своего последнего сообщения, зелёная точка «в сети», значки «закреплён» и «без звука», меню по долгому нажатию.

## Чаты: вторая партия (как в Telegram)

- **Кнопка «вниз»** (`ScrollDownButton`) со счётчиком новых сообщений от других, пришедших, пока смотрели историю; после своей отправки чат сам прокручивается вниз.
- **«Новые сообщения»** — при открытии чата с непрочитанными (`unreadCount` из списка) перед первым из них полоса, и чат прокручивается к нему.
- **Выбор нескольких сообщений** — «Выбрать» в меню сообщения; дальше тап по сообщениям, сверху «Выбрано: N» и действия: копировать, переслать, удалить (только если можно удалить каждое), отмена. «Назад» сначала снимает выбор. Логика — `logic/selection.dart`.
- **@-упоминания** (`logic/mentions.dart`) — как в вебе: в группе при вводе «@» подсказки участников; в поле видно «@Имя» (id спрятан знаками U+2060), на сервер уходит `@[id]`, в сообщении показывается имя; в превью списка — «@участник».
- **Голосовые** — запись удержанием кнопки (`VoiceRecorderController`): влево — отмена, вверх — закрепить запись (кнопки «Удалить»/«Отправить»), слишком короткие отбрасываются; для скринридера долгое нажатие сразу закрепляет запись. В сообщение уходят `durationSec` и `waveform`. Воспроизведение прямо в чате (`VoiceMessagePlayer`): волна с перемоткой касанием, оставшееся время, скорость 1× / 1,5× / 2×, одновременно звучит одно голосовое.
- **Медиа, файлы, ссылки** — в профиле чата «Показать все»: вкладки «Фото и видео» (видео со значком, фото листаются), «Файлы» (размер, дата), «Ссылки» (домен). Берутся последние 8 страниц сообщений (400), об этом сказано внизу.
- Не сделано, потому что нет на сервере: архив чатов, отложенная отправка, пересылка без подписи.
