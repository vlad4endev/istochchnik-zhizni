# Стандарт аватарок в мессенджере

Этот документ фиксирует единые правила рендера аватарок в мессенджере, чтобы избежать "битых" картинок, разных цветов и различий в fallback-поведении.

## 1) Единая точка рендера

- Для любых аватарок в web-клиенте использовать только `AppAvatar`.
- Не писать локальную обработку `onError` в каждом экране, если это обычный аватар.
- Не рендерить `<img>` напрямую для аватарок, кроме специальных случаев с отдельной UX-логикой.

## 2) Единая логика fallback

- Для fallback-буквы использовать `getAvatarInitial(...)` из `avatarUtils`.
- Для fallback-цвета использовать `getAvatarColor(...)` из `avatarUtils`.
- Не дублировать локальные `AVATAR_COLORS` и `getAvatarColor` в компонентах.

## 3) URL и загрузка изображений

- Перед рендером URL должен проходить через `resolvePublicUrl` (это уже делает `AppAvatar`).
- При ошибке загрузки изображения должен показываться fallback без "пустого круга" и без "битой картинки".
- При смене `src` ошибка загрузки должна сбрасываться автоматически (это уже делает `AppAvatar`).

## 4) Где лежит текущий источник истины

- Компонент: `web-react/src/components/AppAvatar.tsx`
- Helper'ы: `web-react/src/features/messenger/avatarUtils.ts`

## 5) Чек-лист для новых экранов

- Есть ли `AppAvatar` вместо прямого `<img>`?
- Используются ли `getAvatarInitial` и `getAvatarColor`?
- Совпадает ли поведение при невалидном URL (корректный fallback)?
- Нет ли локальных дубликатов логики аватарок?
